
Version 3.1.0dev
================

Breaking Changes
----------------

- The ``spat_flexure_correct`` image-processing parameter has been replaced by
  ``spat_flexure_method``; see :ref:`flexure-spatial`.  Use
  ``spat_flexure_method = detector`` instead of ``spat_flexure_correct = True``
  and ``spat_flexure_method = skip`` instead of ``spat_flexure_correct = False``.
  PypeIt files that still use ``spat_flexure_correct`` raise an error with
  these instructions.
- The spatial flexure is now stored for each slit edge, as an array with shape
  :math:`(N_{\rm slits}, 2)`, instead of a single value: e.g., the
  ``sci_spat_flexure`` of the spec2d files, and the ``spat_flexure`` of the
  processed images, the processed calibration frames, and the tilts.  The
  alignment calibration frames now also store their spatial flexure (datamodel
  version 1.2.0).  Processed files from previous versions should be
  regenerated.
- The slit-edge calibration files (``Slits``; datamodel version 1.1.7) now
  record which slit edges were traced, as opposed to inserted (e.g., at the
  detector boundary); see :ref:`flexure-spatial`.  Slit-edge files from
  previous versions must be regenerated.
- The ``ech_direct_cc`` wavelength-calibration parameter (added in version
  3.0.0) has been replaced by ``cc_synth_arc``; use ``cc_synth_arc = False``
  instead of ``ech_direct_cc = True``.


Documentation Updates
---------------------

- Expanded the spatial flexure documentation (:ref:`flexure-spatial`) with a
  description of the algorithm, the available methods, and the frame types for
  which the spatial flexure can be determined.

Functionality/Performance Improvements and Additions
----------------------------------------------------

- Added several methods to determine the spatial flexure, set by the new
  ``spat_flexure_method`` parameter: a single shift for the detector
  (``detector``), a shift for each slit (``slit``), for each slit edge
  (``edge``), or for the left (``leftedge``) or right (``rightedge``) edge of
  each slit.  The per-slit and per-edge values are determined by fitting a
  model of the slit edge to the data, and they can be fit with a polynomial as
  a function of slit position (with outlier rejection), using the new
  ``spat_flexure_polyord`` parameter.  The
  spatial flexure can only be determined for frame types that are processed
  with the slit edges; requesting it for other frame types now raises an error.
- The spatial flexure of each input frame is recorded in the header of the
  datacubes constructed by ``pypeit_coadd_datacube`` (``SPFLXnnn`` keywords);
  see :ref:`coadd3d_spatflex`.
- Added the ``refine_edges`` slit-edge tracing parameter, which shifts each
  traced slit edge to the position of the steepest flux gradient (the traced
  edges are a fraction of a pixel to about a pixel outside it), accounting for
  the light of the neighbouring slit; the traced edge is kept (with a warning)
  if an edge cannot be refined.  It is ``True`` by default for all
  ``SlicerIFU`` spectrographs, so that the edge-based spatial flexure is
  measured relative to the steepest gradient, and a warning is printed if the
  ``edge``, ``leftedge`` or ``rightedge`` spatial flexure method is used with
  ``refine_edges = False``.
- Added the ``spat_flexure_minfrac`` image-processing parameter: if less than
  this fraction of the traced slit-edge pixels coincide with an edge detected
  in the frame at the measured spatial flexure, the slit edges are deemed to
  be undetected, and no spatial flexure is applied to the frame.  The check is
  disabled by default.  For the ``slit``, ``edge``, ``leftedge`` and
  ``rightedge`` methods, the slit edges are deemed to be undetected (and no
  spatial flexure is applied) if fewer than 25% of the slit edges can be
  refined (e.g., for a short exposure of a standard star, where the slit edges
  are not visible), unless at least 50% of the traced slit-edge pixels are
  matched at the detector-level flexure, in which case the detector-level
  flexure is adopted for all edges.  An edge is refined if its model is a
  significant (10 sigma) improvement over a constant flux, and if its position
  is measured to better than 0.1 pixels.  Refined edges whose spatial flexure
  is inconsistent with that of the other edges (by more than 4 times their
  robust scatter about a linear fit across the detector, and at least 0.25
  pixels) are rejected, and their spatial flexure is interpolated from the
  neighbouring edges.
- The detector-level spatial flexure is now the average of the peaks of the
  cross-correlations of the left and right slit edges, computed separately.
  The detected and traced edges are offset from the steepest flux gradient in
  opposite directions for left and right edges, by up to about a pixel, so the
  peak of the single cross-correlation of all edges (as before) was biased
  when the numbers of left and right edges differed, and was unstable when its
  left- and right-edge contributions were similar.  Only the traced slit edges
  are used to measure the spatial flexure, for all methods: the edges inserted
  by the slit-edge tracing (e.g., at the detector boundary, when only one edge
  of a long slit is on the detector) are assigned the spatial flexure of the
  other edge of their slit.  If the traced edges on a detector are all on one
  side of the slits (e.g., a long slit cut by the detector boundary), the
  detector-level spatial flexure would be biased by up to about a pixel, so
  the traced edges are refined (for all methods), and each slit is assigned
  the spatial flexure of its traced edge (or, if none of them can be refined,
  the detector-level spatial flexure, provided that the slit edges are clearly
  detected).  If none of the slit edges were traced (e.g., if the slits were
  placed at the detector boundaries with ``bound_detector = True``), no
  spatial flexure is applied.  If the left- and right-edge peaks differ by
  more than 2.5 pixels (e.g., because the edges of one side are poorly
  detected), the peak of the single cross-correlation of all edges is used
  instead.  Each peak, and the fraction of the traced edge pixels of its side
  that it matches, are printed in the log.
- The spatial flexure of each frame is accounted for when constructing
  datacubes (``pypeit_coadd_datacube``): the RA and Dec of each detector pixel,
  and the astrometric alignment traces, are now evaluated using the spatial
  flexure of the frame (relative to that of the alignment frame).  The
  alignment and scattered-light calibration frames are now processed with the
  slit edges, so that their spatial flexure can be determined if requested
  (this is not done by default for the alignment frames).
- The manual spatial flexure correction (a value in the pypeit-file ``shift``
  column; see :ref:`flexure-spatial-manual`) now applies to any frame type
  that is processed using the slit traces, including background and
  calibration (arc, tilt, and flat-field) frames; it previously only applied
  to science and standard frames.
- Added the ``cc_synth_arc`` wavelength-calibration parameter.  If False, the
  arc spectra are cross-correlated directly with the archived arc spectra (by
  the ``full_template`` and ``holy-grail`` methods, and for the ``echelle``
  method order identification), instead of first building synthetic
  line-only arcs (and, for the order identification, continuum-subtracting
  the correlation function).  This is much faster for large spectral formats
  (used by ``shane_hamspec``); the default (True) preserves the original
  behavior.  For the order identification, this replaces the
  ``ech_direct_cc`` parameter.
- Added the ``stack_slits`` wavelength-calibration parameter for the
  ``full_template`` method.  For multislit, IFU, and fiber data, the arc
  spectra of all slits are aligned to a reference slit and combined into a
  single arc spectrum with a higher S/N, which is calibrated against the
  archived template; the arc lines of each slit are then identified using the
  solution of the combined spectrum.  This allows data with weak or few arc
  lines to be calibrated with a high S/N template, without requiring any
  single slit to be calibrated on its own.  The reference slit is set by
  ``reference_slit`` or, if not set, chosen automatically.  A QA plot of the
  solution of the combined spectrum is written to
  ``QA/PNGs/Arc_1dfit_*_stack.png``.  See :ref:`wvcalib-stack-slits`.


Instrument-specific Updates
---------------------------

- Keck/LRIS: the traced slit edges of long-slit observations are now refined
  to the steepest flux gradient (``refine_edges = True``), since the spatial
  flexure of such frames (with one slit edge on each detector) is measured
  from the refined slit edge; see :ref:`flexure-spatial`.
- Keck/KCWI and Keck/KCRM: the spatial flexure is now determined by default
  for the arc, tilt, pixel-flat and illumination-flat frames (``edge``
  method) and for the science frames (``detector`` method, with
  ``spat_flexure_minfrac = 0.25``); the slit edges of science frames are only
  illuminated by the sky, and the edges of individual slits cannot be
  measured reliably, whereas the detector-level shift is consistent to a few
  thousandths of a pixel between consecutive exposures.  The traced slit
  edges are refined to the steepest flux gradient (``refine_edges = True``),
  and the slit edges are no longer
  tweaked (``tweak_slits = False``), so that everything is relative to the
  initial slits.  Other changes to the KCWI/KCRM defaults:

  - The wavelength calibration cross-correlates the arc spectra directly
    with the templates (``cc_synth_arc = False``), instead of synthetic arc
    spectra.
  - KCWI: the non-linearity correction (``correct_nonlinear``) and the
    subtraction of the scattered light from the pixel and illumination flats
    (``subtract_scattlight``) are no longer applied by default; they can be
    switched on by the user.  The default ``spat_samp`` and
    ``tweak_slits_thresh`` of :ref:`flatfieldpar` are now used.

- Keck/KCWI and Keck/KCRM: ``stack_slits`` is now used by default for the
  wavelength calibration (see :ref:`wvcalib-stack-slits`).
- Keck/KCRM: the RH3 and RM1 ``full_template`` templates
  (``keck_kcrm_RH3.fits`` and ``keck_kcrm_RM1.fits``) have been rebuilt.  The
  high S/N coadds used for part of these templates had been resampled onto a
  linear wavelength grid, whereas the ``full_template`` method requires the
  template to be sampled on the detector pixels; the coadds are now resampled
  onto the detector pixel grid of the corresponding grating setting before the
  templates are built.  The two settings that make up the RH3 template are
  now joined at 8600 Angstroms (previously 8920 Angstroms).

Bug Fixes
---------

- Wavelength solutions that pass exactly through the identified arc lines
  (i.e., with zero degrees of freedom and an RMS of zero) are no longer
  accepted.  If there are too few lines for the requested ``n_final``, the
  order of the final fit is reduced so that at least two degrees of freedom
  remain (with a warning), and the fit fails if fewer than four lines are
  available.  Previously, a handful of misidentified lines could produce an
  apparently perfect, but incorrect, wavelength solution.
- Fixed a crash (``AttributeError``) in the wavelength calibration when the
  slit given by ``reference_slit`` could not be calibrated; a clear error
  message is now raised instead.  Also fixed a crash in the echelle wavelength
  calibration when the fit of an order fails.
- Fixed the 2D Gaussian fit of the white-light image of a datacube
  (:func:`~pypeit.core.datacube.fitGaussian2D`), used to find point sources in
  ``pypeit_extract_datacube`` and to determine the datacube weights and
  alignment.  The model was not normalised to its integrated flux, the initial
  flux and offset did not depend on the image, and the position of a
  DAOStarFinder detection was constrained to within one third of the FWHM, so
  that the fit of a poorly sampled object often failed (or ended at the
  bounds).  The fit now starts from the centroid of the brightest pixel near
  the DAOStarFinder detection (whose position can be wrong by more than a
  pixel for a poorly sampled object), the position is constrained to within
  the larger of the FWHM and one pixel, and a circular Gaussian is fit before
  the elliptical one (whose orientation is undetermined at a circular initial
  guess).  If the elliptical fit fails, the circular fit is adopted; if both
  fail, the initial position and the input FWHM are adopted with a warning.
- Fix the sign of the spatial flexure correction applied when evaluating the
  wavelength tilts of a frame (e.g. a science frame) whose spatial flexure
  differs from that of the tilt frame.  The tilts were evaluated at a spatial
  position shifted in the wrong direction (i.e., twice the relative flexure
  away from the correct position).  The tilts are now evaluated at the same
  fractional position along the slit in the tilt frame, which also accounts
  for a different flexure of the left and right slit edges.
- The relative spectral illumination correction (``use_specillum``) is now
  applied at the spatial flexure of each flat-fielded frame.  It was applied
  at the spatial flexure of the pixel flat, which gave the wrong correction
  near the slit edges when the two flexures differed.
- Fix the flat-field model of slits (or echelle orders) whose edges are closer
  than about the ``slit_illum_pad`` padding of :ref:`flatfieldpar` to the edges
  of the neighbouring slit.  Where the padded footprints of two slits overlap,
  the overlapping pixels are assigned to only one of the slits, but some of
  them are within the other slit.  For those pixels, the fit of the spectral
  response of their slit used the spectral coordinate of the first spectral
  row (instead of their wavelength tilts), and the spectral model of their slit
  was not evaluated, so that the pixel flat of up to about two pixels per
  spectral row near the slit edge could be wrong by up to a factor of 2.  The
  wavelength tilts and the spectral and spatial models of each slit are now
  evaluated over its own padded footprint.  Also, the pixels of each slit are
  now always used to fit its spatial (illumination) response (they could be
  assigned to the padding of the neighbouring slit, so that the illumination
  profile of their slit was extrapolated there), and the gap between two
  slits whose padded footprints overlap is split at its midpoint (it was
  assigned to the second slit).  See the new ``split_overlap`` option of
  :func:`~pypeit.slittrace.SlitTraceSet.slit_img`.
- ``pypeit_coadd_datacube``: dedicated sky frames (``skysub_frame``) and
  relative scale-correction frames (``scale_corr``) are now remapped to the
  slits of each science frame, accounting for the spatial flexure of both
  frames; they were applied pixel by pixel.  The grating correction
  (``grating_corr``) is now calculated using the spatial flexure and
  wavelength image of the pixel flat, so it no longer depends on which
  science frame first used the Flat calibration file.  See
  :ref:`coadd3d_spatflex`.
- The spatial flexure is now measured relative to the unpadded traced slit
  edges.  For spectrographs that pad the slit edges (the ``pad`` parameter of
  :ref:`edgetracepar`; e.g., APF/Levy and ARC/ARCES), the cross-correlation
  template and the edge refinement used the padded edges, which biased the
  measured spatial flexure.  The docstrings of
  :func:`~pypeit.slittrace.SlitTraceSet.select_edges` and related methods now
  state that their ``pad`` argument is added to the global padding.
- Fix the RA and Dec assigned to serendipitous sources (``SERENDIP``) in
  slitmask observations when the spatial flexure is determined.  Their offset
  from the slit center was measured relative to the slit center without the
  spatial flexure of the frame, so their coordinates were shifted by the
  spatial flexure along the slit.
- ``pypeit_coadd_2dspec``: the reference traces about which the frames are
  coadded now include the spatial flexure of each frame.  Frames with
  different spatial flexure were misregistered by the difference in flexure
  when the offsets were provided by the user, or taken from the file headers
  or the slitmask design (the automatically determined offsets absorbed the
  flexure).  The wavelength grid built from the slits
  (``use_slits4wvgrid``) also uses the slit edges shifted by the spatial
  flexure of each frame.
- ``pypeit_coadd_datacube``: fix the relative scale of the default sky frame
  when ``skysub_frame = default`` is given for a frame in the ``spec2d`` block
  of the ``coadd3d`` file; the relative scale was multiplied by the exposure
  time of the science frame.
- Spectral flexure was not previously included when generating a wavelength
  image for a spec2d file during ``global_skysub``. This caused a multiple
  correction to the spectral flexure, and only affected IFU data reduction.


Version 3.1.0dev
================

Breaking Changes
----------------

- PypeIt no longer uses a remote-control connection to a separately launched
  ``ginga``.  All displays (``pypeit_show_2dspec``, ``pypeit_view_fits``,
  ``pypeit_show_1dspec``, the ``pypeit_chk_*`` scripts, ``run_pypeit
  --show``, and the debugging displays) now open a ``ginga`` window that runs
  inside the PypeIt process; see :ref:`pypeit_ginga_viewer`.  There is no
  need to start ``ginga --modules=RC,SlitWavelength`` before running PypeIt.
  Displays now *pause* the code that opens them: scripts exit when the window
  is closed, and reductions continue when the window is closed (the next
  display opens it again).  Displays do not wait in headless sessions
  (``QT_QPA_PLATFORM=offscreen``), under ``pytest``, or when
  ``PYPEIT_VIEWER_NOWAIT=1``.
- Removed the ``SlitWavelength`` ginga plugin, which was only used to receive
  images through the remote-control connection.  The wavelength (and, with
  ``pypeit_show_2dspec --show_wave_rms``, wavelength RMS) readout is still
  shown, by :class:`~pypeit.display.slitwavelength.SlitImage`.

Functionality/Performance Improvements and Additions
----------------------------------------------------

- Much faster ``ginga`` displays.  Images and overlays are passed directly to
  a ``ginga`` viewer running in the PypeIt process instead of being sent to a
  separate ``ginga`` process (e.g., ~0.6 s instead of ~9 s to show a 4k x 4k
  image with its wavelength map).  Slit edges and object traces are drawn
  only for the part of the image in view, with a limited number of vertices,
  so panning and zooming stay fast.  For more than 200 traces (e.g., the
  Binospec IFU fibers), traces are only drawn when zoomed in enough to
  distinguish them; hovering over a trace highlights it and shows its name.
  ``pypeit_show_2dspec`` therefore now shows the overlays for the Binospec
  IFU, which were previously skipped.
- Added the ``Spec2dView`` ginga plugin used by ``pypeit_show_2dspec``.  Its
  panel allows selecting the detector/mosaic and toggling the images and the
  overlays shown, without restarting the script or reloading the other
  images.

Script Changes
--------------

- The ``Spec1dView`` panel of ``pypeit_show_1dspec`` has a new "Keys" button
  that lists the keyboard and mouse shortcuts of the plot; typing 'h' with the
  cursor on the plot does the same.  The listing now includes the smoothing
  keys, and the documented ``singlequote`` key (set the X range to the marked
  region) now works.
- ``pypeit_show_1dspec`` (and the ``Spec1dView`` ginga plugin) can now show
  files with a single spectrum (:class:`~pypeit.onespec.OneSpec`), such as the
  coadds produced by ``pypeit_coadd_1dspec``.  Added
  :func:`~pypeit.onespec.is_onespec_file` to identify these files.
- ``pypeit_show_2dspec --no_clear`` and the new ``pypeit_view_fits
  --no_clear`` option send the file to an already open PypeIt viewer
  (opened by either script) and return immediately; see :ref:`pypeit_show_2dspec`.
- Added the ``--no_clear`` and ``--chname`` options to
  ``pypeit_show_1dspec``.  With ``--no_clear``, the spectrum is added to an
  already open PypeIt viewer (opened by ``pypeit_show_1dspec``,
  ``pypeit_show_2dspec``, or ``pypeit_view_fits``), in a channel named after
  the file, and the script returns immediately; see :ref:`pypeit_show_1dspec`.
  The dashboard uses this option, so the spectra viewed from it are collected
  in one window.
- ``pypeit_show_2dspec`` and ``pypeit_view_fits`` read the file (and, for
  spec2d files, check its datamodel version) before opening the ginga window,
  so problems are reported immediately, in the terminal.
- The Setup GUI now shows raw files with ``pypeit_view_fits``, in a single
  separate window.
- ``pypeit_qlview`` now runs the quicklook viewer in a separate process that
  uses PypeIt's in-process ginga viewer (no remote-control connection), and
  returns immediately.  Added the ``--no_clear`` option, which opens the
  viewer in an already open PypeIt viewer, and the ``--foreground`` option,
  which runs the viewer in the same process and returns when its window is
  closed.
